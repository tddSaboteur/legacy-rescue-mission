- [x] **Вылазка #1: Взятие в плен модуля camel-ftp**
    * Залита стартовая точка — оригинальный код компонента из недр Apache Camel (версия 4.21.0).
    * *Состояние:* Божественные классы намертво сшиты с библиотекой JSch. Родные юнит-тесты протухли, при переносе в изолированный модуль контекст взрывается ошибками `ResolveEndpointFailedException`.
    * *Точка фиксации:* Коммит `feat: Взятие в плен модуль camel-ftp...`

- [x] **Вылазка #2: Подавление саботажа конфигураций фреймворка**

    * *Точка фиксации:* Тег `v0.2.0-stabilized-green` (сборка ожила, но идет 11 минут сетевого ада).

- [x] **Вылазка #3: Лингвистический барьер и локаль Awaitility**
    * Локализован и подавлен капризный баг, когда тесты падали из-за русской локали ОС (`В соединении отказано` вместо английского `Connection refused`). Оставлен защитный `//todo` маркер.

- [x] **Вылазка #4: Вытеснение зависимостей (Dependency Shifting)**
    * Проведена масштабная эвакуация потрохов из `SftpOperations` в тяжелый инфраструктурный клиент `JschSftpClient`.
    * Вынесены логгер, настройки `SocketFactory`, `Proxy`, интерактивный ввод (`UIKeyboardInteractive`, `UserInfo`) и методы управления жизненным циклом каналов `ChannelSftp`.
    * Создан санитарный кордон для проверяемых исключений — оригинальный `SftpException` переводится в кастомный `JschSftpClientException` с сохранением ID кодов ошибок протокола.
    * *Точка фиксации:* Тег `v1.0.0-dependency-shifted` (бизнес-логика избавлена от импортов JSch-исключений).

- [x] **Вылазка #5: Разбор инфраструктурного монолита на роли**
