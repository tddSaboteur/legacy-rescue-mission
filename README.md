# 🛠️ Пролетарская Кузница TDD (proletarian-tdd-forge)

> "Разработчики всех стран, застрявшие в легаси без бюджетов! Нам нечего терять, кроме своих костылей." — *Из Манифеста TDD-Диверсанта.*

Добро пожаловать на анонимный испытательный полигон инженерного сопротивления. Этот репозиторий — художественная реконструкция реального корпоративного ада, перенесенная в безопасный сеттинг космических кораблей для обхода NDA.

## 💣 Наша Цель
Показать на живом, грязном примере, что каноны красивых книжек работают даже там, где теоретические тесты "в лоб" бессильны. Мы берем запущенный спагетти-код, находим "швы", изолируем модули и закладываем TDD-мины замедленного действия, превращая хаос в чистую архитектуру.

## 🚩 Хроники Освобождения Труда (План вылазок):

- [x] **Вылазка #1: Взятие в плен модуля camel-ftp**
    * Залита стартовая точка — оригинальный код компонента из недр Apache Camel (версия 4.21.0).
    * *Состояние:* Божественные классы намертво сшиты с библиотекой JSch. Родные юнит-тесты протухли, при переносе в изолированный модуль контекст взрывается ошибками `ResolveEndpointFailedException`.
    * *Точка фиксации:* Коммит `feat: Взятие в плен модуль camel-ftp...`

- [x] **Вылазка #2: Подавление саботажа конфигураций фреймворка**
    * В ручном режиме экспроприирован каталог `generated/resources/META-INF` и зафиксирован в тестовых ресурсах, чтобы Camel увидел собственные фабрики компонентов.
    * *Точка фиксации:* Тег `v0.2.0-stabilized-green` (сборка ожила, но идет 11 минут сетевого ада).

- [x] **Вылазка #3: Лингвистический барьер и локаль Awaitility**
    * Локализован и подавлен капризный баг, когда тесты падали из-за русской локали ОС (`В соединении отказано` вместо английского `Connection refused`). Оставлен защитный `//todo` маркер.

- [x] **Вылазка #4: Вытеснение зависимостей (Dependency Shifting)**
    * Проведена масштабная эвакуация потрохов из `SftpOperations` в тяжелый инфраструктурный клиент `JschSftpClient`.
    * Вынесены логгер, настройки `SocketFactory`, `Proxy`, интерактивный ввод (`UIKeyboardInteractive`, `UserInfo`) и методы управления жизненным циклом каналов `ChannelSftp`.
    * Создан санитарный кордон для проверяемых исключений — оригинальный `SftpException` переводится в кастомный `JschSftpClientException` с сохранением ID кодов ошибок протокола.
    * *Точка фиксации:* Тег `v1.0.0-dependency-shifted` (бизнес-логика избавлена от импортов JSch-исключений).

- [x] **Вылазка #5: Разбор инфраструктурного монолита на роли**
    * Уничтожено процедурное перекидывание объекта `Session` туда-сюда. Выделена независимая `SftpSessionFactory` и отдельный объект `JschSocketFactory`.
    * Группировка разрастающихся параметров в чистые объекты Java `record`. Рефакторинг перенесен в собственную безопасную зону.
    * *Точка фиксации:* Тег `v1.1.0-session-factory-extracted`.

- [x] **Вылазка #6: Выделение интерфейса SftpClient**
    * [x] Минимизировать взаимодействие SftpOperations с JschSftpClient, что бы SftpOperations не знал внутренней реализации JschSftpClient.
    * [x] Выделить интерфейс SftpClient из оставшегося APi JschSftpClient.
    * *Точка фиксации:* Тег `v1.2.0-client-api-stabilized`.

- [x] **Вылазка #7: Пишем первый Unit на SftpOperations**
    * [x] Убрать упоминание о внутренней реализации JschSftpClient в его методах.
    * [x] Сделать первый примитивный тест на SftpOperations.connect при подключенном клиенте.
    * [x] Восстановить отключенный запуск тестов mvn:verify.
    * *Точка фиксации:* Тег `v1.3.0-first-unit-test`
